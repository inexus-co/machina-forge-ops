# Machina Forge Ops

**エージェントに、顧客のサーバのシェルは渡しません**

他人のサーバを保守するためのデスクトップアプリケーションです。画面（RDP または VNC）、
端末（SSH）、その両方を扱えるエージェントが、ひとつのウィンドウの中にあります。
保守される機械には、何も入れません。

二つの習慣の代わりに作りました。ひとつは、コーディングエージェントをサーバの中で走らせること。
もうひとつは、リモートデスクトップと端末とモデルとの会話を、別々の三つの窓で持つこと——それぞれに
接続し、それぞれに尋ねる。これはその三つを一箇所に置いたもので、しかもエージェントには、
向こう側のシェルを一度も渡しません。

**顧客のサーバには何も入れません。** すべては既にある接続の上から読み取り、**読み取れなかったものは
推測せず、そう画面に書きます。**

![作業画面：RDPのデスクトップ、SSHの端末、エージェントが一つの窓に](docs/media/ja-workspace.gif)

*一つの窓に一台のサーバ。RDP のデスクトップ、SSH の端末、そしてその隣にエージェント。監視アラートは
届いたまま貼り付けています。* **[実行の全体を2分の動画で（日本語版）](https://github.com/inexus-co/machina-forge-ops/releases/tag/demo)**

## できること

- **画面**：RDP は自前のヘルパー（`native/rdp`）で、FreeRDP を使い、変化した矩形だけを fd 3 に流します。
  ウィンドウも X11 も常駐も要りません。VNC は TypeScript で直接しゃべります。**SSH が無いサーバも、
  触れないサーバではありません**——エージェントが画面を読み、クリックとキーで操作します。1操作ごとに
  人が止め、その時に狙っていた画面と一緒に記録に残ります。
- **端末**：SSH（`ssh2` と `xterm.js`）。`tmux` があれば、アプリを閉じても作業は続きます。
  すでに何かを見ている最中なら、**その端末をチャットに渡せます**——画面の中身が、あなた自身の言葉として
  引用符付きで名前を添えてエージェントに渡り、記録にも残ります。
- **エージェント**：Pi（`@earendil-works/pi-coding-agent`）。モデルは複数登録でき、実行ごとに選べます。
  名前をつけたエージェントは、それぞれ自分のモデル・承認の求め方・1回の実行で使えるコマンド数の上限を持ちます。
- **委譲**：エージェントは別のエージェントに仕事を渡せます。渡された側は自分のモデルで動き、深さは1段まで、
  コマンド数の上限は親と共有し、承認も記録もすべて親に集まります。
- **状態・構成・ファイル**：すでに開いている SSH 接続の上から読みます。相手側には何も置きません。
- **台帳**：そのサーバについて操作者が書いたこと、過去の実行が申し送ったこと、この機械が読み取ったこと。
  次の実行に引き継がれるので、誰も何もない状態から始めずに済みます。
- **プラグイン**：何度も出会う形のサーバ（LAMP・Nginx・Docker・PostgreSQL）についての出来合いの知識と、
  見慣れないサーバをパスを当てずに調べる手順。プラグインはスキルの集まりで、goal を持つスキルはチャットの
  ＋ メニューのコマンドにもなります。この機械のフォルダから追加できます——**何も取りに行きません。**

![SSHの無いサーバ：エージェントがデスクトップを右クリックし、承認カードには狙っていた画面が付く](docs/media/ja-screen-agent.gif)

***SSH がまったく無い**サーバです。エージェントが画面を読んで操作します。1操作ごとに人が止め、
記録には操作の前と後が残ります。*

## 安全について

すべてのコマンドは、この順で四つの層を通ります。

1. **形**。`;` `&&` `|` `>` バッククォート・改行は不可。パスとして書かれたコマンドも不可。
   1行に1コマンド、さもなければ実行しません。
2. **底**。`sudo`、破壊的なもの、デバイスを指すもの、機械全体を歩き回る読み取りは、**常に人に止まります。**
   どの設定でも、覚えさせた例外でも、これは緩みません。
3. **カタログ**。約600のコマンドを、読む・書く・動詞・コード・シェルに人手で分類してあります。加えて
   ディストリビューションが説明している全コマンド。読むものは走り、書くものは止まり、シェルは拒否され、
   **誰も判断していないものは止まって、そう言います。**
4. **操作者自身の例外**。導入ごと・サーバごとに、作業中の承認カードから作ります。

![承認カード：パイプを含むコマンドは門前払い、対象サーバで走らせないものは理由付きで却下、出力のパスワードは伏せられる](docs/media/ja-approval.gif)

*本物の実行です。`; & |` の入ったコマンドは門前払い、`perl` や `sed` は「対象サーバでは実行できません」と
理由付きで却下され、パスワードらしきものはモデルにも記録にも届いていません。*

すべてのコマンドとその出力は実行記録に入ります。資格情報らしきものは、モデルにも記録にも届く前に出力から
取り除かれます——鍵の名前は残るので、エージェントは「パスワードが設定されている」ことは見えても、
その値は決して見えません。

**アカウントもテレメトリもありません。** 登録も計測もせず、この機械から出ていくのは、操作者が選んだ
モデルへ送るものだけです。そのモデルは、自分のネットワークの中のエンドポイントでも構いません。

資格情報（サーバのパスワード、鍵のパスフレーズ、モデルの API キー）は、メインプロセス側の暗号化された
保管庫にあり、**画面には二度と戻りません。** 空のまま保存すれば、既に入っているものが使われます。

**モデルが計算する場所は、顧客の機械ではなく、あなたの機械です。** エージェントには本物のシェルを
渡します——パイプもリダイレクトもスクリプトも。ただしサンドボックスの中で、書けるのはその実行の作業
ディレクトリだけ、あなたのホームは読めず、ネットワークはありません。サーバに届くのは、上の四層を
通った**1行ずつのコマンド**だけです。

![設定変更の承認カード。差分と新しい全文が出ている](docs/media/ja-changing-a-file.gif)

**ファイルの変更は手順が決まっています。** 現物を取ってきて（**控えはあなたの機械にも**ハッシュ付きで
残します——修理中の機械の上だけに置いた控えは、その機械と一緒に死ぬので）、サーバ側にも控えを取り、
新しい内容はサンドボックスの中で作り、**差分と新しい全文を承認カードに出します——自動実行モードでも
必ず**。書いたあとは、そのソフト自身の検査（`nginx -t` のような1行）を通してから反映します。

## なぜこの作りなのか

判断の記録です。費用と、却下した案も書いてあります。

- [ADR 0001 — エージェントはシェルを持ってよい。ただしこの経路のために書かれた保証の下で](docs/decisions/0001-shell-under-a-written-guarantee.md)
- [ADR 0002 — コードは自分たちの側で実行し、対象には監査できる入力だけを送る](docs/decisions/0002-code-runs-on-our-side.md)

どちらも英語です。上の四層・サンドボックス・ファイルの手順の根拠であり、**それぞれがどこで効かなく
なるか**も書いてあります。

## これでは守れないもの

- **画面操作のエージェントには許可リストがありません。** デスクトップ上に端末の窓を見つければ、そこへ
  何でも打てます。四層はどれも効きません。だから1回の実行は画面かシェルのどちらかで、両方は持ちません。
  画面の経路があるのは、SSH がまったく開いていないサーバのためだけです
- **許可リストは、分類した人の賢さまでしか賢くありません。** `find -exec` や `-delete` は引数を走査して
  止め、`awk` と `sed` はコマンドではなくコードとしてサーバ上では拒否します。ただし**まだ誰も気づいて
  いない抜け道**を持つプログラムは、誰かが分類するまで通ります。見つけたら教えてください
- **プロンプト注入は防げません。** エージェントが読むもの——ログの1行、設定ファイル、ファイル名——は
  モデルに届き、その中の文章は指示になり得ます。被害を抑えるのはモデルの判断力ではなく関門です：
  分類されていないものは走らず、昇格は人なしに走りません。それでも、汚染されたログから**もっともらしい
  理由の付いた、承認可能なコマンド**は提案され得ます。最後の砦は、カードを読む人間です
- **承認疲れは実在します。** 自動モードがあるのはそのためで、有効にするかはサーバごとの取引です
  （それでも底——sudo・破壊的・デバイス——は止まります）
- **壁はその機械のOSの分だけです。** 隔離する手段が1つも無い機械——WSL2 も Docker も無い Windows——では、
  手元のシェルは**そもそも出しません**。明示的に責任を引き受けたときだけ例外があり、既定は無効、
  1行ずつ承認、記録には「壁なしで走った」と残ります
- **監視システムではありません。** 誰かが作業している間に機械を読むものです。1週間のグラフや午前3時の
  通報には常駐するものが要り、それは別の製品です

## どれがどこで動くか

| | 画面（RDP） | 画面（VNC） | 端末・ファイル・エージェント | 署名 |
|---|---|---|---|---|
| **macOS** | ○ | ○ | ○ | 無し——初回は右クリック → 開く |
| **Windows** | まだ <sup>1</sup> | ○ | ○ | 無し |
| **Linux** | ○ <sup>2</sup> | ○ | ○ | 該当なし |

<sup>1</sup> RDP の画面は FreeRDP の上に載せた自前のヘルパーで、Windows 用はまだ書いていません。
<sup>2</sup> Linux 用ヘルパーは Linux 上でしか作れません（Mac からは作れない）。FreeRDP の
ライブラリは同梱せず機械のものを使うので、FreeRDP 3 が入っていることが前提です。macOS では
アプリの中に入って一緒に運ばれます。

**署名はしていません。** アドホック署名なので起動はしますが、別の Mac では初回に「開発元を確認できない」と
言われます。右クリック → 開く を一度行うか、`xattr -dr com.apple.security.quarantine <アプリ>` で消して
ください。きちんと配るには Developer ID 証明書と公証が要ります。

カタログの第二層は、ディストリビューション自身から採ったものです——**Ubuntu 24.04・Debian 12・
RHEL UBI 9・Rocky Linux 9・AlmaLinux 9**。それ以外のサーバでも動きます。誰も判断していないものは、
止まってそう言うだけです。

## 言語

画面は英語・日本語・簡体字中国語・繁体字中国語。設定で選び、再起動なしで切り替わります。
ソースは英語です。コードの中の文はすべて英語で書き、`src/shared/messages/` で翻訳します。訳の抜けが
あるとテストが落ちます。エージェントへの指示のうち操作者の言語に従うのは1行だけ——「何語で答えるか」です。

## 開発

```bash
yarn install
yarn dev          # 起動
yarn typecheck
yarn test         # 単体と統合
yarn build
```

RDP のヘルパーは動かす機械ごとにビルドします。開発中も画面にはこれが要ります
（FreeRDP 3 が必要：`brew install freerdp`）。

```bash
native/rdp/build.sh
```

### パッケージ

```bash
yarn dist:mac     # dist/ に dmg と zip、arm64 と x64
yarn dist:win
yarn dist:linux
```

同梱するもの：ヘルパー本体と、それが必要とする FreeRDP のライブラリ（`bundle.sh` が `@loader_path` に
書き換えます）。パッケージのたびに作り直し、外のライブラリを指したままのものは同梱しません——
画面のないアプリを配るほうが、開いた瞬間に死ぬアプリを配るよりましだからです。

統合テストは本物のコンテナに接続し、無ければ黙って飛ばします。

```bash
docker compose -f native/rdp/test-server/compose.yaml up -d --build
```
